# 상품등록 지연 원인과 작업 방식 교정

기록일: 2026-09-10 KST

## 현재 확인된 사실

- 중앙 작업본은 tracked 변경 53개와 untracked 경로 118개, 합계 171개 경로가 정리되지 않은 상태다.
- 2026-09-10 중앙 검토 문서가 33개 생성됐다.
- 공용 등록 경로 세 파일은 각각 2,599줄, 1,969줄, 2,746줄이며 채널 분기 검색 결과가 66개다.
- 쿠팡 작업은 OPTIONS r1/r2 이후 lost-create reconciliation, durable reconciliation 001/002, source revision 003, completeness 004, readiness 005, official-source hardening과 006 CAS로 계속 세분됐다.
- 반복된 로컬 테스트와 중앙 검토는 많았지만 현재 중앙 코드로 만든 신규 상품의 실제 CREATE 및 공식 원격 확인은 0/8이다.
- 엄격한 외부 증거 기준은 19/48 = 39.6%다. 구조적 코드 존재 8/8과 실제 자동등록 완료 0/8을 섞지 않는다.

## 지연의 직접 원인

1. **안정된 중앙 기준점 부재**: 병렬 산출물이 들어오는 동안 중앙 작업본이 계속 바뀌어 이전 기준의 패치를 다시 만들거나 되돌렸다.
2. **수평 확장**: 한 채널을 실제 등록까지 닫기 전에 여덟 채널의 source, approval, readiness, CAS, reconciliation 계약을 동시에 확장했다.
3. **공용 대형 파일 충돌**: 모든 채널이 같은 route, worker runtime, workbench를 수정해 병렬 개발 결과가 독립적으로 끝나지 않았다.
4. **검토의 재귀화**: 패치마다 별도 독립 검토를 추가하고 그 검토 결과를 다음 번호의 작업으로 다시 배정했다. 테스트 통과가 실제 등록 실행을 대신했다.
5. **완료 단계 미실행**: 배포, 새 SKU provider CREATE, 공식 GET, 판매자/구매자 화면 확인, 내부 published/live 수렴을 계속 다음 작업으로 넘겼다.
6. **실제 외부 제약**: 일부 채널은 앱 승인, OAuth, 권한, 배송·반품 정책 ID 같은 계정별 값이 필요하다. 이는 채널별 blocker지만 3주 전체를 설명하지는 않는다.

## 즉시 적용할 중복 방지 규칙

- 쿠팡 신규 SKU 한 건이 끝날 때까지 신규 hardening 번호, 신규 추상화, 과거 상품 복구 기능을 추가하지 않는다.
- 현재 중앙 코드에 이미 있는 검사와 테스트를 다시 구현하지 않는다.
- 같은 파일을 두 작업이 동시에 수정하지 않는다. 중앙 소유 파일은 중앙에서 한 번만 편집한다.
- 로컬 테스트 완료를 진행률의 최종 단계로 계산하지 않는다.
- provider write 직전 blocker가 나오면 같은 작업을 재시도하지 않고 정확한 입력 또는 외부 승인 하나만 해결한다.
- 성공 기준은 새 SKU의 중복 부재 GET, CREATE 1회, sellerProductId와 option/status 공식 GET, SellerPilot durable receipt와 published/live 수렴이다.

## 다음 실행선

1. 현재 쿠팡 005와 중앙 hardening까지를 기준선으로 고정한다.
2. 006은 현재 provider mutation 직전 CAS에 꼭 필요한 최소 변경만 남기고 추가 설계를 중단한다.
3. 기존 UI에서 실제 신규 검증 상품의 19개 입력값과 상세 승인 상태를 채운다.
4. 로컬에서 동일 요청을 실행해 job 생성, claim, provider 호출 직전까지 단 한 번 통과시킨다.
5. 운영 적용이 허용된 실행 단계에서 새 SKU 하나만 중복 조회 후 CREATE 1회 실행한다.
6. 공식 GET과 SellerPilot 원장 수렴을 확인한 뒤에만 쿠팡을 현재 코드 기준 완료로 올린다.
7. 이 세로 경로를 템플릿으로 삼아 나머지 채널에 적용하되, 채널별 외부 승인 blocker만 분리한다.

## 금지 사항

- 기존 remote ID나 과거 성공 SKU로 신규 등록 완료를 주장하지 않는다.
- HTTP 202, queue, local test, migration 파일, provider 호출 시도를 외부 등록 성공으로 계산하지 않는다.
- 실패 원인을 모른 채 재시도하거나 에이전트에게 같은 범위를 다시 배정하지 않는다.
- 중앙 적용 전에 오래된 patch를 다시 적용하지 않는다.
