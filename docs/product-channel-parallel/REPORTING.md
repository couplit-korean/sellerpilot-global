# 채팅 보고에 의존하지 않는 상품등록 작업 규칙

2026-09-09 사용자 최신 요청을 반영한다. 이 문서는 기존 시작 보고·중간 보고 메시지 규칙보다 우선한다. 채널별 소유권과 실제 상품 실행 배정 규칙은 유지한다.

## 채널 담당

- 자기 reports 폴더의 status.md/status.json에 변경 결과, 근거, 다음 실행 항목을 기록한다. 임시 파일에 완전히 기록한 후 rename으로 교체한다. 비밀 및 고객 원문은 기록하지 않는다.
- 시작·계획·진척·검사 통과·일반 통합 요청은 중앙 채팅에 반복 전송하지 않는다. 보고 파일 갱신으로 제출한다. 제출 자체를 완료로 간주하거나 중앙 답장만 기다리지 않는다. 자기 범위 구현·공식 문서 대조·필수값 검증·오류 처리·전용 테스트 등 독립 작업을 계속한다.
- 공통 변경 제안은 reports 폴더 안에 고유 요청 ID와 revision으로 보존한다. 기준 커밋, 대상 파일별 before SHA256, 최소 patch, 호출/필드 계약, 검사 명령과 결과, ready/frozen 여부, 의존 요청 ID를 포함한다. 동결본은 덮어쓰지 말고 새 revision으로 수정한다.
- 자기 소유 파일 외의 공통 코드·타 채널 파일·중앙 폴더·통합 원장은 수정하지 않는다. 소유권 애매한 파일은 공통 제안으로 제출한다.
- 각 담당은 변경에 필요한 전용 테스트를 실행한다. 전체 테스트와 전체 빌드를 8개 작업에서 매번 중복 실행하지 않는다. 중앙에서 통합 영향 범위를 검사한다.
- 사용자만 가능한 인증/입력이나 즉각 대응해야 하는 중요한 실패만 직접 메시지로 알린다. 외부 차단은 구체 근거와 재개 조건을 파일에 남기고 가능한 독립 작업을 계속한다. 실행할 일이 실제로 없으면 대기를 정확히 기록한다.
- 실제 provider 쓰기는 기존 승인 대상과 요청 식별자에 대해 중앙이 실행 담당을 하나로 배정한 후 진행한다. 실등록을 임의 병렬 발행하지 않는다. 기존 요청의 결과가 불명확하면 먼저 재조회한다.

## 0번 수집·통합

정본 폴더에서 다음 명령을 실행한다.

```sh
python3 scripts/collect-product-channel-reports.py
```

ownership.json이 지정한 8개 reports 폴더를 읽어 `.local/product-channel-inbox/inbox.json`과 snapshots에 수집한다. 채널·경로·내용 SHA256이 같은 항목은 중복 생성하지 않는다. 이미 수집한 수정본은 원본이 덮어써지거나 지워져도 보존한다. 수집되지 않은 중간 수정본까지 보장하는 것은 아니므로 동결 제출은 고유 revision 파일로 유지한다. 이 로컬 상태는 Git에서 제외하며 비밀을 넣지 않는다.

1. 기존 heartbeat는 먼저 수집기를 실행하고 pending 항목의 보존된 스냅샷을 읽는다. 단순 상태, 공통 의존 요청, 동결 제출을 구분한다. 메시지가 없어도 발견한다.
2. 공통 의존 요청과 동결 제출을 순서대로 검토한다. 현재 파일 해시와 patch 적용 가능성을 검사한 후 한 건씩 적용한다. 오래된 before hash를 강제 덮어쓰지 않는다. 담당자가 편집 중인 파일을 임의 복사하지 않는다.
3. 관련 회귀 및 업무/채널 경계 검사를 마친 뒤 근거를 기록한다. 검토만 한 보고는 reviewed, 실제 통합·검증한 제출만 integrated로 표시한다. 막힌 항목은 blocked와 재개 조건을 기록하고 다른 작업을 계속한다.
4. 읽지 않은 항목을 일괄 완료 처리하지 않는다. 새 revision은 다시 pending으로 들어온다. 명시적 처리는 다음과 같다.

```sh
python3 scripts/collect-product-channel-reports.py --ack ITEM_ID reviewed '검토 근거와 후속 작업'
```

5. 작업 상태도 묶어서 확인한다. idle이면서 실행 가능한 구체 항목이 있으면 해당 항목으로 재개한다. 같은 인증/심사 차단만 무의미하게 반복 호출하지 않는다.
6. 채널 담당에게 필요한 반영 결과·새 계약·실행 배정은 중앙이 전달한다. 불필요한 수신 확인 왕복은 하지 않는다. 사용자에게는 의미 있는 완료·실패·필수 입력만 알린다.

수집기는 잠금과 원자적 교체로 동시 수집의 목록 손실을 막는다. 코드 통합을 자동 실행하거나 모든 편집을 잠그는 도구는 아니다. 공통 코드 적용은 0번 한 담당이 순차 수행한다. 10분 heartbeat는 앱 스케줄러 실행 조건에 의존하며 실시간 무중단 서비스라는 보장이 아니다.

## 진행 중 사용자 메시지 처리

30분 보고 설정이나 현재 상태 질문에 답하는 중에도 진행 중인 중앙 통합 항목을 잃지 않는다. 수집 성공을 통합 완료로 표시하지 않는다. 종료/전환 전에는 실제 적용 파일, 검사 결과, 아직 검토하지 않은 제출, 다음 행동을 중앙 체크포인트에 남긴다. 다른 작업 조회가 최신 turn의 items를 빈 배열로 반환하면 채팅 본문을 읽었다고 표현하지 않고, 상태 스냅샷과 동결 보고 파일을 대조한 범위만 기록한다.
