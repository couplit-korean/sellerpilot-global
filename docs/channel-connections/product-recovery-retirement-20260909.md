# 과거 상품 전용 복구 코드 제거 — 2026-09-09

사용자 요청: 과거 상품을 복구하기 위한 예외 코드가 신규 상품등록 개발을 복잡하게 하지 않도록 제거한다. 작업 기준은 로컬 통합 체크아웃이며, 실제 판매 상품과 운영 데이터는 삭제하지 않는다.

## 제거한 실행 경로

- 과거 상품 ID·SKU·원격 상품번호에만 적용하던 8채널 후보 판정, 대표 이미지 예외, 가격 5,000원/재고 1 고정, 닫힌 등록 제한을 특정 상품에만 열어 주던 RPC 호출 및 전용 enqueue 분기.
- eBay·쿠팡·11번가·Lazada·스마트스토어·Qoo10의 exact 복구 helper와 Temu·Shopee SG의 과거 상품 전용 수정/채택 helper.
- 11번가 cookie-create recovery, Qoo10 S1 전용 release 2개, Shopee/Temu 기존 상품 채택 API: 총 5개 route. 해당 주소는 빌드 라우트에서 제거된다.
- 삭제한 기능만 검증하던 전용 테스트 88개 파일과 복구용 CLI/증거 스크립트 4개. 혼합 테스트에서는 일반 상품등록·수정·식별 검증을 유지했다.

앱·라이브러리의 전용 파일 27개와 스크립트 4개를 삭제했다. 공통 실행 파일 내부에서도 해당 분기를 제거했다. 기존 운영 migration과 시점별 조사 문서는 적용/감사 이력으로 보존하며 신규 개발의 실행 지침으로 사용하지 않는다.

## 일반 기능이 따르는 경로

`상품 작업대 → /api/admin/channel-operations → 승인 상세/계정/상품 원장 확인 → 일반 release gate → gateway → lib/product-registration/channels/{channel}.ts → 원격 재조회 → 결과 기록`

- 특정 과거 상품번호를 이유로 새 요청을 허용하거나 금액/재고를 덮어쓰지 않는다.
- 일반 중복 방지, 자격 소유/판매자 식별, 요청 중복 제어, 승인 이미지 검증, 원격 상품 재조회, 결과 불명 상태의 재시도 제한을 유지한다.
- 일반 eBay 수정은 서버가 조회한 listingId/SKU/offerId/marketplaceId의 일치를 확인한다. 일반 Qoo10 등록 실패 뒤 롤백이 입증된 수정은 서버 원장의 롤백 증거를 검증한다. 이 두 경로에는 과거 상품 상수가 없다.
- Shopee SG 생성은 특정 상품·merchant 번호가 아닌 현재 상품 문맥과 선택된 유효 merchant/shop을 검증한다. 임의 상품 ID는 허용하지만 SKU와 shop 불일치는 거부한다.
- Lazada 일반 수정은 중앙 KRW 가격·재고와 MYR 변환 정책의 일치를 계속 확인한다. 일반 원장 가격 결속도 유지한다.
- Temu의 삭제한 기존 상품 수정 분기를 일반 수정 구현으로 간주하지 않는다. 현재 일반 `listing.update` 미지원 상태를 유지한다.
- OAuth 연결 복구, 일반 수동 상품 연결, 승인된 외부 상세 이미지 가져오기는 과거 상품 복구 예외와 별도 기능이므로 유지한다.

## 오래된 요청 처리

`lib/channels/retired-product-recovery.ts`는 폐기된 요청 표식만 식별하는 작은 차단 함수다. 상품 ID·계정·가격 상수나 복구 실행 코드를 보유하지 않는다.

- API는 작업 원장 claim 전에 이전 복구 요청에 HTTP 410을 반환한다.
- gateway provider와 상품 실행기는 자격 갱신·이미지 처리·provider 변경 전에 `PRODUCT_RECOVERY_RETIRED`로 거부한다.
- 내부에 중첩된 과거 publication source도 검사한다. 오래된 큐 요청이 일반 수정으로 잘못 실행되지 않는다.
- 기존 상품번호가 값으로 들어 있다는 사실만으로 거부하지 않는다. 정상 상품등록·수정의 일반 검증을 따른다.

## 함께 보존한 11번가 보완

앞선 작업의 유료배송 필드·주소/배송비 readback 검증을 보존했다. 단일 재고행 GET→PUT→GET 어댑터와 16개 로컬 검사는 남겼으나, 재고 동기화 API·DB 통합이 끝나지 않은 상태를 지원 완료로 표시하지 않도록 공개 inventory 기능은 보류했다. 이번 제거 작업에서 운영 재고를 바꾸지 않았다.

## 검증 및 전달 범위

최종 TypeScript 전체 **2,763/2,763**, 업무 격리 **40/40**, 채널 격리 **28/28**, 전체 타입 검사와 경계 검사 포함 로컬 Next.js 빌드가 통과했다. **변경 파일 55개 ESLint·Git diff 검사 통과**, 보존한 OAuth 재인가 검사 3/3도 통과했다. [검증 요약/로그 해시](product-recovery-retirement-verification-20260909.json). 삭제한 기능의 테스트 개수 감소는 일반 기능 완성도 상승으로 계산하지 않는다.

상품/CS/배송의 6방향 업무 의존 및 채널 간 실행 의존은 경계 검사로 확인한다. 모든 검증은 로컬 코드 기준이며 채널 등록 성공이나 운영 DB 반영을 의미하지 않는다.

private `origin`의 `integration-aside`에 코드와 문서를 전달한다. Vercel 연결 원격·배포·운영 DB·provider 상품·고객 답변은 변경하지 않는다. 운영에 이미 설치된 과거 migration/RPC를 삭제하거나 적용했다고 보고하지 않는다.
