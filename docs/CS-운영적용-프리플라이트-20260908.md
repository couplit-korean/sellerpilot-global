## 5. 비파괴 롤백

애플리케이션 오류가 있으면 직전 운영 release로 먼저 되돌린다. 후보 migration은 기존 데이터와 기존 RPC를 삭제하지 않는 additive/wrapper 변경이므로 즉시 drop/rename으로 되돌리지 않는다. 이전 코드는 그대로 동작하고 새 private 원문 및 검색 RPC는 사용되지 않은 채 남는다.

Shopee comment migration이 preimage 검사에서 실패하면 transaction이 시작 상태로 돌아가므로 운영 함수를 수동 rename하지 않는다. 적용 뒤 Shopee wrapper만 문제가 있으면 새 job 생성을 멈춘 뒤 현재 job/원장 snapshot을 보존하고, 검토된 후속 migration으로 wrapper 본문을 교체한다. 기존 ingest 이름을 즉석 rename하는 방식은 실행 중 job과 함수 의존성을 깨뜨릴 수 있어 사용하지 않는다.

Lazada raw inbox와 archive v2에 쌓인 데이터는 롤백 중 삭제하지 않는다. 보관기간 prune과 RLS를 유지하며, 재배포 뒤 같은 digest/cursor로 재처리한다. provider mutation이나 고객 답변은 자동 재시도하지 않고 기존 reconciliation 계보를 먼저 읽는다.

## 6. 운영 100% 판정에서 별도로 남는 외부 조건

이 적용 묶음만으로 8채널 운영 100%가 되지는 않는다. Qoo10 별도 리뷰는 공식 QAPI 전체 Method 목록에 조회·댓글 API가 없고, Shopee 구매자 Chat의 앱 권한·응답 계약, Lazada IM 앱 permission, 11번가 판매자 계정과 Q&A/긴급알리미 상세 계약, Temu inactive 앱과 반려된 compliance, eBay Commerce Message scope 403은 각 공급자/계정 조건이 해결돼야 한다. eBay는 1년 상세 전수 읽기도 Trading 요약과 같은 고유 9건이었고 판매자센터 21행 중 12개 플랫폼 행은 현재 Trading API 집합 밖으로 확정했으므로, 별도 권한이 생기기 전에는 판매자센터 직접 열람 대상으로 남긴다.
