# SellerPilot 운영 배포·인증 체크리스트

이 문서는 코드로 완료할 수 없는 계정 승인 지점만 모은 운영 체크리스트다. 비밀번호, API Key, OAuth Code, Access Token 원문은 문서·Git·터미널 로그에 기록하지 않는다.

## 1. Supabase 프로젝트 승인과 마이그레이션

대상 프로젝트 소유 계정으로 Supabase CLI 또는 Dashboard에 로그인한 다음 `supabase/migrations`의 파일을 이름순으로 적용한다.

```bash
supabase login
supabase link --project-ref <PROJECT_REF>
supabase db push
```

적용 순서와 목적:

1. `20260816060000_channel_credentials_and_roles.sql` — 관리자, Vault 자격증명, 감사기록
2. `20260816065848_sellerpilot_ai_cli_jobs.sql` — 비공개 AI 작업 큐와 Storage 정책
3. `20260816103854_ai_operations_controls.sql` — AI 이력, 재시도, 취소, 임대 연장, 보관 정리
4. `20260816104732_operations_core.sql` — 상품, 게시상태, 주문, CS, 마진, 운영 감사 원장
5. `20260816110000_lazada_token_refresh.sql` — Lazada Access Token 만료 전 자동 갱신과 Vault 버전 교체
6. `20260816120321_expand_channel_connectors.sql` — 쿠팡·11번가·스마트스토어·eBay 실행 계층
7. `20260816133601_add_shopee_connector.sql` — Shopee 자격증명·작업·토큰 자동 갱신

첫 앱 관리자는 Supabase Auth 사용자 생성 후 SQL Editor에서 명시적으로 승인한다.

```sql
insert into sellerpilot_private.admin_users (user_id, display_name)
select id, 'SellerPilot Admin'
from auth.users
where lower(email) = lower('<APP_ADMIN_EMAIL>')
on conflict (user_id) do update set display_name = excluded.display_name;
```

완료 증거:

- 앱 로그인 후 `운영 DB · Supabase 관리자 데이터` 배지 표시
- 상품 10개, 주문 5개, CS 4개의 초기 검증 데이터가 관리자 계정에 1회 생성
- 비관리자 계정은 대시보드 대신 권한 안내 화면 표시

## 2. Vercel 환경변수와 정리 작업

Couplit 소유 Vercel 프로젝트의 Preview와 Production에 아래 값이 있어야 한다.

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- `SUPABASE_SECRET_KEY`
- `CRON_SECRET` — 새 무작위 값, Production 전용 관리 권장

`vercel.json`의 `/api/internal/maintenance`는 매일 03:17 KST에 Lazada Access Token의 72시간 이내 만료 여부를 확인해 자동 갱신하고, 완료된 지 90일이 지난 AI 입력·결과와 작업 레코드를 정리한다. `CRON_SECRET`이 없거나 다르면 401/503으로 거부해야 정상이다.

## 3. Qoo10 인증 게이트

`API 키 · 인증` 화면에서만 Qoo10 Seller ID, Certification Key, 승인된 읽기 검사 상품번호를 입력한다. 저장 즉시 원문은 Supabase Vault로 이동한다. 연결 검사는 Qoo10 공식 상품 상세 읽기 API의 성공 응답을 확인하며, 테스트상품 쓰기는 사용자 승인 범위가 확정되기 전 실행하지 않는다.

## 4. Lazada 인증 게이트

`API 키 · 인증`에 App Key·App Secret을 입력하면 앱이 일회성 OAuth state를 HttpOnly 쿠키에 저장하고 Lazada 승인 화면으로 이동한다. 복귀 후 code는 즉시 URL에서 제거하고 state를 검증한 뒤 서버에서 토큰으로 교환해 Vault로 옮긴다. 단, 실제 토큰 교환과 판매자 읽기 검사는 개발자 콘솔 White IP와 동일한 고정 공인 송신 IP가 필요하다.

## 5. Shopee 인증 게이트

`API 키 · 인증`에 Live Partner ID·Partner Key를 입력하면 최신 `https://open.shopee.com/auth` 승인 링크로 이동한다. Main account 콜백의 code·main_account_id·state를 검증하고 반환된 8개 shop_id별 Access/Refresh Token을 Vault에 분리 저장한다. API 실행 검수 JSON의 `shopId`로 국가 숍을 선택하며 해당 숍 토큰만 만료 전에 갱신한다.

## 6. 쿠팡·네이버 인증 게이트

- 쿠팡: WING 로그인 → 우측 판매자명 → 추가판매정보 → 비밀번호 재확인 → OpenAPI Key 확인/발급 순서다. 키는 180일 유효하고 만료 14일 전부터 재발급할 수 있다. Vendor ID·Access Key·Secret Key를 운영 화면에 한 번만 입력한 뒤 등록상품 목록 1건 읽기를 통과시킨다.
- 네이버: 스마트스토어 통합매니저 계정으로 Commerce API센터 개발업체 계정을 생성하고 내 스토어 애플리케이션을 등록한다. 판매자 상품·주문 API는 `SELLER` 유형과 판매자 UID(`account_id`)를 사용하며 토큰은 180분이다. `GW.AUTHN` 401이면 서버가 토큰을 한 번 재발급하고 동일 요청을 재시도한다.

## 7. ChatGPT CLI·codex-image 작업자

1. Mac의 Codex CLI에서 `codex login status`가 `Logged in using ChatGPT`인지 확인한다.
2. 웹의 `API 키 · 인증` 화면에서 작업자 토큰을 발급한다.
3. `npm run ai:worker:install`을 실행하고 보안 입력창에 토큰을 넣는다.
4. Temu를 사용할 작업자에서 `npm run ai:worker:temu-egress`를 실행하고, 같은 공인 IP를 Temu Partner Platform 허용 목록에 등록한다.
5. `npm run ai:worker:status`에서 `실행 중`, `키체인 토큰: 저장됨`, `Temu 작업자 허용 IP: 설정됨`을 확인한다.
6. 대표사진을 포함한 상품 사진으로 AI 작업 1건을 실행해 분석 JSON, 대표 연출컷, 1:1·4:5·16:9 이미지가 모두 생성되는지 확인한다.

모바일·웹 사용자는 SellerPilot API만 호출하고 Temu 비밀값이나 허용 IP를 전달받지 않는다. Temu 호출은 채널 작업자에서만 실행하며, 공인 IP가 바뀌면 `TEMU_EGRESS_IP_CHANGED`를 기록하고 허용 목록 갱신 전까지 자동 발행을 중지한다. 여러 작업자를 운영할 때는 모든 송신 IP를 등록하거나 단일 고정 egress 게이트웨이 뒤에 배치한다.

## 8. Production 승격 기준

- Preview에서 로그인 → DB 초기화 → 상품 AI 생성 → 상품 원장 반영 → 마진 저장 → 주문 상태 변경 → CS 답변 저장 흐름 통과
- Qoo10 읽기 API 통과
- Shopee 8개 숍 토큰 교환과 각 숍 `get_shop_info` 읽기 통과
- Lazada 고정 IP 및 OAuth 토큰 교환 통과
- Vercel Runtime Log에 비밀 원문이나 고객 개인정보가 남지 않음
- Shopee 라우트·메뉴·자격증명·8개 숍 선택이 있고 Alibaba·1688은 비활성 상태

위 증거가 없는 배포는 Preview로만 유지하고 Production 별칭으로 승격하지 않는다.

## 9. 현재 계정 인증 게이트

- Vercel CLI는 `couplitofficial-4206` 계정과 `sellerpilot-global` 프로젝트에 연결돼 있다.
- 현재 Chrome의 Supabase 프로필과 연결된 Supabase 커넥터는 Couplit 운영 조직이 아닌 다른 계정을 보고 있다.
- 따라서 Couplit 소유 Supabase 프로젝트로 계정을 전환하기 전에는 운영 DB 마이그레이션을 적용하지 않는다.
