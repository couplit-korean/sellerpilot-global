# SellerPilot 운영 배포·인증 체크리스트

이 문서는 코드로 완료할 수 없는 계정 승인 지점만 모은 운영 체크리스트다. 비밀번호, API Key, OAuth Code, Access Token 원문은 문서·Git·터미널 로그에 기록하지 않는다.

## 1. Supabase 프로젝트 승인과 마이그레이션

Couplit 운영 프로젝트 소유 계정으로 Supabase CLI 또는 Dashboard에 로그인한 다음, 현재 연결 대상의 project ref를 운영 환경변수와 대조한다. 다른 프로젝트에 연결된 상태에서는 적용하지 않는다. `supabase/migrations`를 이름순으로 확인하고 아직 적용되지 않은 파일만 forward 방식으로 적용한다. 이미 적용된 migration 파일은 수정하지 않는다.

```bash
supabase login
supabase link --project-ref <PROJECT_REF>
supabase db push
```

이번 릴리스의 마지막 보정은 `20260828210000_non_cs_release_integrity.sql` 한 파일이다. Vercel 채널 작업의 claim/complete 규격, 지원 operation 허용표, OAuth 응답 비밀값 제거, 동일상품 공급자 상태, 멈춘 작업 회수, 판매채널용 정규화 이미지 보관 원장을 함께 맞춘다. 이 파일 뒤에 같은 목적의 임시 migration을 추가하지 않는다.

첫 앱 관리자는 Supabase Auth 사용자 생성 후 SQL Editor에서 명시적으로 승인한다.

```sql
insert into sellerpilot_private.admin_users (user_id, display_name)
select id, 'SellerPilot Admin'
from auth.users
where lower(email) = lower('<APP_ADMIN_EMAIL>')
on conflict (user_id) do update set display_name = excluded.display_name;
```

완료 증거:

- `supabase_migrations.schema_migrations`에 정확한 최신 version이 한 번만 기록됨
- PGlite 전체 migration 테스트와 운영 프로젝트 Advisor 확인 통과
- 앱 로그인 후 `운영 DB · Supabase 관리자 데이터` 배지 표시
- 비관리자 계정은 대시보드 대신 권한 안내 화면 표시
- 운영 상품·주문·문의 데이터는 QA 편의를 이유로 생성하거나 삭제하지 않음

## 2. Vercel 환경변수와 정리 작업

Couplit 소유 Vercel 프로젝트의 Preview와 Production에 아래 값이 있어야 한다.

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`
- `SUPABASE_SECRET_KEY`
- `CRON_SECRET` — 새 무작위 값, Production 전용 관리 권장
- `SELLERPILOT_SERVERLESS_STATIC_EGRESS_CHANNELS` — **Vercel Static IP와 판매채널 허용 목록이 실제로 일치한다고 검증된 채널만** 쉼표로 설정

`서버 사용량` 화면까지 사용할 경우에만 Vercel·Supabase Management API의 읽기 전용 환경변수를 추가한다. 값이 없으면 화면은 사용량을 추정하지 않고 `연결정보 없음`으로 표시한다.

- `VERCEL_ACCESS_TOKEN`, `VERCEL_TEAM_ID`
- `SUPABASE_ACCESS_TOKEN`, `SUPABASE_PROJECT_REF`, `SUPABASE_ORGANIZATION_SLUG`

`vercel.json`은 maintenance를 매일 실행하고, 상품조사·주문/문의 동기화·동일상품 가격 갱신을 5분 간격으로 서로 다른 분에 배치한다. 완료된 AI·판매채널 이미지와 직접 식별 데이터는 30일 보관 원장에 따라 정리한다. `CRON_SECRET`이 없거나 다르면 401/503으로 거부해야 정상이다.

Vercel Static IP는 별도 유료 기능이다. 사용자 승인 없이 구매하거나 켜지 않는다. 이미 활성화된 경우에만 실제 송신 IP, 쿠팡·스마트스토어·11번가·Temu 허용 목록, Supabase 고정 egress 정책을 대조한 뒤 `SELLERPILOT_SERVERLESS_STATIC_EGRESS_CHANNELS`에 해당 채널을 추가한다. 플래그만 먼저 켜서는 안 된다.

## 3. Qoo10 인증 게이트

`API 키 · 인증` 화면에서만 Qoo10 Seller ID, Certification Key, 승인된 읽기 검사 상품번호를 입력한다. 저장 즉시 원문은 Supabase Vault로 이동한다. 연결 검사는 Qoo10 공식 상품 상세 읽기 API의 성공 응답을 확인하며, 테스트상품 쓰기는 사용자 승인 범위가 확정되기 전 실행하지 않는다.

## 4. Lazada 인증 게이트

`API 키 · 인증`에 App Key·App Secret을 입력하면 앱이 일회성 OAuth state를 HttpOnly 쿠키에 저장하고 Lazada 승인 화면으로 이동한다. 복귀 후 code는 즉시 URL에서 제거하고 state를 검증한 뒤 서버에서 토큰으로 교환해 Vault로 옮긴다. 단, 실제 토큰 교환과 판매자 읽기 검사는 개발자 콘솔 White IP와 동일한 고정 공인 송신 IP가 필요하다.

## 5. Shopee 인증 게이트

`API 키 · 인증`에 Live Partner ID·Partner Key를 입력하면 최신 `https://open.shopee.com/auth` 승인 링크로 이동한다. Main account 콜백의 code·main_account_id·state를 검증하고 반환된 8개 shop_id별 Access/Refresh Token을 Vault에 분리 저장한다. API 실행 검수 JSON의 `shopId`로 국가 숍을 선택하며 해당 숍 토큰만 만료 전에 갱신한다.

## 6. 쿠팡·네이버 인증 게이트

- 쿠팡: WING 로그인 → 우측 판매자명 → 추가판매정보 → 비밀번호 재확인 → OpenAPI Key 확인/발급 순서다. 키는 180일 유효하고 만료 14일 전부터 재발급할 수 있다. Vendor ID·Access Key·Secret Key를 운영 화면에 한 번만 입력한 뒤 등록상품 목록 1건 읽기를 통과시킨다.
- 네이버: 스마트스토어 통합매니저 계정으로 Commerce API센터 개발업체 계정을 생성하고 내 스토어 애플리케이션을 등록한다. 판매자 상품·주문 API는 `SELLER` 유형과 판매자 UID(`account_id`)를 사용하며 토큰은 180분이다. `GW.AUTHN` 401이면 서버가 토큰을 한 번 재발급하고 동일 요청을 재시도한다.

## 7. ChatGPT CLI·codex-image 작업자

1. Mac의 Codex CLI에서 `codex login status`가 `Logged in using ChatGPT`인지 확인한다.
2. 웹의 `API 키 · 인증` 화면에서 범위가 분리된 토큰 세트를 발급한다. 판매채널·스케줄러 토큰은 세트 활성화 증명에만 사용하며 로컬 런타임 권한으로 사용하지 않는다.
3. 화면에 표시된 `npm run ai:worker:install:ai-only -- --rotate-token --token-set <UUID>`를 실행하고 세 보안 입력창에 해당 범위 토큰을 넣는다. 설치기는 처음부터 `--ai-only`로 기동한다.
4. `npm run ai:worker:status`에서 `실행 중`과 `AI 전용`을 확인한다. `all-scopes`, `gateway-only`, `scheduler`가 로컬에서 실행 중이면 운영 전환을 중단한다.
5. 대표사진을 포함한 상품 사진으로 AI 작업 1건을 실행해 분석 JSON과 요청된 이미지가 생성되는지 확인한다.

모바일·웹 사용자는 SellerPilot API만 호출하며, 로컬 AI 작업자는 판매채널 큐를 가져오거나 Temu·쿠팡·스마트스토어·11번가 API를 호출하지 않는다. 판매채널 작업과 주기 실행은 Vercel·Supabase 경로만 사용한다.

서버리스 작업자는 운영 배포와 단일 migration 적용 후 아래 순서로 구성한다. 명령은 비밀값을 출력하지 않으며 정확한 운영 Supabase host가 아니면 중단한다.

```bash
pnpm gateway:serverless:configure -- --bootstrap
pnpm gateway:serverless:configure -- --canary --activate --status
```

canary는 작업을 claim하거나 외부 채널을 호출하지 않는다. 같은 실행에서 canary가 성공한 경우에만 Supabase의 분단위 wake scheduler를 활성화한다.

## 8. Production 승격 기준

- Preview에서 로그인 → 상품 AI 생성 → 상품 원장 반영 → 마진 저장 → 진행/히스토리 → 상품 수정 흐름 통과
- Production에서 serverless canary, scheduler status, maintenance·channel-sync·competitor cron 인증 확인
- 390px iPhone, 344/330px Galaxy Fold 커버, 데스크톱에서 동일 핵심 흐름 통과
- Qoo10 읽기 API 통과
- Shopee 8개 숍 토큰 교환과 각 숍 `get_shop_info` 읽기 통과
- Lazada OAuth와 안전한 읽기 진단 통과
- 고정 egress 4개 채널은 Vercel Static IP·판매채널 허용 목록·DB 정책·요청 attestation이 모두 확인된 경우에만 `지원`으로 표시
- Vercel Runtime Log에 비밀 원문이나 고객 개인정보가 남지 않음
- 외부 상품 게시·배송 확정·고객 답변은 사용자가 정확히 승인한 테스트 대상이 있을 때만 실행

위 증거가 없는 배포는 Preview로만 유지하고 Production 별칭으로 승격하지 않는다.

## 9. 계정·브라우저 인증 게이트

- Vercel·Supabase 브라우저 검증은 작업 직전에 Chrome 인스턴스를 다시 조회하고 `profileName: JEONGHUN`인 정확한 인스턴스에서만 수행한다.
- 판매채널·개발자센터 검증은 같은 방식으로 `profileName: CHANGHEE`에서만 수행한다.
- 필요한 프로필이 연결되지 않았으면 다른 프로필이나 전체 화면 Computer Use로 우회하지 않는다.
- CLI를 사용할 때도 대상 Vercel 프로젝트와 Supabase project ref를 배포 직전에 다시 읽고 운영값과 일치하지 않으면 중단한다.
