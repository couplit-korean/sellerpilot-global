# 생성 경로 재점검 — 2026-09-07

작업 브랜치 codex/product-scene-profiles와 v2/v3 스크립트를 확인했다. 운영 배포 확인 기록이 아니다.

## 확인한 원인
- 서버 buildServerStudioBackgroundPrompt가 빈 배경만 생성하고 상품·패키지를 금지한다. settingShotAsset이 나중에 원본 컷아웃을 붙인다.
- CLI backgroundOnly 분기는 원본 --image 인자를 이미지 모델에 전달하지 않는다. 사진 여러 면을 참조해 완성 장면을 만드는 경로가 아니다.
- profile-setting-shots는 원본 시점과 합성 사각형을 고정하고 배경 구조 외 소품을 제한한다. 63개 프로필을 늘려도 상품과 장면을 함께 생성하지 않는다.
- source-evidence는 원본 전체 프레임을 붙이던 경로였다. 이전 턴의 미커밋 수정은 사진별 컷아웃을 사용하도록 바꿨다.
- normalizeIdentityBackgroundPlate가 alpha<255인 모든 픽셀을 흰색으로 바꾸었다. 이전 턴 미커밋 수정은 실제 알파 혼합으로 색·조명을 보존한다.
- v2/v3는 직접 검토한 마스크/문안과 채팅 배경 생성이 섞인 제작본이었다. 빈 배경 생성 도구의 중간 결과도 그대로 노출되어 요청과 어긋났다.

## v4 재제작 계약
- 사진 4장을 직접 참조해 상품이 포함된 완성 사진을 생성한다.
- BEYOND ORIGIN, 애사비 젤리스틱, 파랑·노랑 포장, 붉은 사과 그림, 닫힌 상자 하나를 유지한다.
- 제품 촬영·책상·외출 준비 맥락을 사용하고 주방을 자동 배정하지 않는다.
- 미제공 낱개 포장, 내용물, 효능, 새로운 수량은 만들지 않는다.
- 영양·성분·제조 표시는 원본 분리 이미지와 직접 확인한 텍스트로 유지한다.
- 매장 사진 전체를 상세페이지에 넣지 않는다.
- 상품 유무, 형태·브랜드·상품명, 매장 배경 잔존, 장면 차이를 직접 확인한다.
- HTML의 이미지 포함 여부·문구·레이아웃을 별도 확인한다.

v4는 여기에서 새 직접 참조 생성 지침으로 만든 결과다. 서버/CLI의 전환이나 운영 배포 완료를 의미하지 않는다. 이전 미커밋 코드는 별도 검토 대상으로 보존한다.
