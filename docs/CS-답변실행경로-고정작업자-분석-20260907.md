# 쿠팡·스마트스토어 CS 답변 실행 경로 분석

2026-09-07 운영 읽기 조사. 고객 답변·작업 접수·정책 변경을 하지 않았다.

## 확인된 현재 상태

- 운영 runtime SHA `b778d6c57f1bf0bc6111bb362d881b73436c87e1`에서 DB static egress 정책은 쿠팡 false, 스마트스토어 true다. 이는 실제 공급자 통신 성공이나 IP 허용 증거가 아니다.
- 두 채널의 `local_channel_executor_access(channel,'inquiries.reply')`는 모두 NULL이다. 실제 답변 job과 delivery는 각각0건이다.
- API `app/api/admin/cs/reply/route.ts`는 두 채널에서 Vercel 환경 및 DB의 serverless static egress 설정만 검사한다. 현재 Mac 문의 조회 성공이 이 검사 통과를 뜻하지 않는다.
- 운영 최상위 enqueue 함수 SHA256 `101e88ce8e894a68607e7559401578f91f9fdf210e2729493658e7e2d8c21e8f`는 스마트스토어 상품 답변에서 static 정책을 다시 확인한다. 나머지 경로는 `sellerpilot_31033000_enqueue_inquiry_reply_unsafe` SHA256 `b9f7c2753758eddb727677144f3c3636458908a361359246f6fadfdc60537e91`의 쿠팡/스마트스토어 static 정책을 통과해야 한다.
- 현재 reply context/delivery 조회는 승인 관리자 공유이며, ticket-owner와 수집 credential의 created_by 결속을 검사한다. CS14에서 고치는 새 조회3종의 creator-only 회귀와는 구분된다.
- 기존 general local executor는 상품/카테고리 계약이고 쓰기에서 `listing_mutation_release_gate_is_effective`를 요구한다. CS 답변을 그 상품 작업 경로에 끼워 넣으면 상품 등록 게이트와 CS가 다시 중첩된다.

## 후속 구현 계약

1. CS 전용 실행기 경로를 만든다. 채널·운영 credential·인증된 판매자·worker token·정확한 release SHA·등록 확인된 egress·만료시각을 결속한다. 상품 승인/게시 게이트와 분리한다. 기존 serverless 정책을 true로 꾸며 Mac을 허용하지 않는다.
2. API는 화면에서 받은 실행기 값으로 목적지를 정하지 않는다. 서버가 검증한 문의·credential 및 DB의 현재 route로 전송 가능 여부를 판정한다. UI는 ‘경로 검증됨’과 실제 ‘답변 확인됨’을 구분한다.
3. enqueue는 기존 ticket lock, 최신 inboundKey, provider waiting 상태, native 답변 대상, 원문 fingerprint, 이전 미확정 작업 격리를 유지한다. job에 정확한 CS 경로/worker/release를 결속하고 다음 관리자 접속에도 같은 문의·원장 계보를 유지한다.
4. claim과 외부전송 직전에도 route 유효성·worker 생존·lease·판매자·release·IP를 재검증한다. 다른 worker나 serverless가 해당 로컬 전용 답변을 가져가면 안 된다.
5. 공급자 요청 전 거절은 재검토 가능한 오류, 요청 후 결과 불명은 reconciliation_required로 남긴다. 응답 불명을 성공이나 자동 재전송으로 바꾸지 않는다. 새 고객 문의·답변 대상 변경은 기존 검토를 무효화한다.
6. DB/API/worker 동시 계약을 검증한 뒤 배포한다. API의 static 조건만 삭제하거나 기존 내부 unsafe 함수를 직접 노출하는 수정은 하지 않는다.

## 완료 검증

- 정확한 승인 경로1개에서만 enqueue/claim 가능, credential/owner/판매자/release/IP/worker/만료 불일치는 모두 거절한다.
- 동일 문의·inboundKey·답변 중복 접수 방지, 동시 작업·lease 상실·늦은 provider 응답에서 중복 전송하지 않는다.
- 상품 등록 gate가 닫혀 있어도 유효한 CS 경로 판정은 독립적이며, CS 경로를 켜도 상품 쓰기 허용은 넓어지지 않는다.
- 승인 관리자≠최초 등록자인 실제 운영 관계를 테스트한다. 비관리자와 직접 테이블 접근은 계속 거절한다.
- 실제 고객 전송은 대상·내용의 명시 승인이 있는 경우에만 실행하며, 접수/외부응답/원격조회/웹표시를 각각 기록한다.

이 문서는 읽기 분석이다. 새 CS route/SQL/API 변경은 아직 구현·운영 적용하지 않았다. 총괄의 스마트스토어 등록 복구 작업과 충돌하지 않게 후속 통합한다.
