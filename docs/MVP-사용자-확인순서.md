# 상품 등록·CS MVP — 사용자 확인 순서

대상 화면: https://sellerpilot-global.vercel.app . 실제 채널 작동 검증은 사용자가 수행한다. 주문·배송은 이번 확인 범위가 아니다. 아래 구현·배포 상태와 판매채널의 실제 처리 결과는 별개다.

## 상품 등록

1. `상품 등록`에서 기존 이미지·상세페이지를 선택하고 상품명·가격·재고·카테고리와 채널 필수 속성을 입력한다. 배송비·출고지 같은 등록 필수 정보는 입력하되 송장·배송 업무는 테스트하지 않는다.
2. 유사상품 결과 위의 `이번 유사상품 검색 기준`에서 기준 상품명·검색 요청어·보조 검색어를 확인한다. 상품 정보를 고치면 `다음 유사상품 검색 기준`으로 바뀌며 재검색 전임을 표시한다. 등록할 채널과 판매자/마켓을 선택하고 화면의 필수 입력 검사를 확인한다. 처음에는 채널 하나씩 실행하면 오류 위치를 쉽게 확인할 수 있다.
3. 등록을 실행하고 `등록 진행 · 히스토리`에서 접수, 처리 중, 성공/실패와 채널 상품 번호를 확인한다.
4. 판매자센터에서 해당 상품과 이미지·상세페이지·가격이 원하는 대로 등록됐는지 직접 확인한다. 결과가 미확정이면 같은 등록을 다시 누르지 않고 그 작업의 오류를 전달한다.

## CS

1. `CS`에서 확인할 채널을 선택하고 문의 수집/새로고침을 실행한다.
2. `미처리 문의`와 `전체 문의`를 구분해 실제 고객 문의가 표시되는지 확인한다. 시스템 알림과 반품/환불 조회 결과는 일반 구매자 채팅과 다르다.
3. 실제 답변할 문의를 선택해 내용을 작성하고 전송한다. 내부 초안 저장, 전송 대기, 외부 전송 완료 표시를 구분해 확인한다.
4. 판매자센터에서 답변이 같은 문의에 도착했는지 확인한다. 오류를 알려 줄 때는 채널, 누른 버튼, 오류 문구, 작업/문의 번호를 보내면 된다. 비밀번호나 API 키는 보내지 않는다.

## 개발 수정 및 실행 경계

상품 등록용 기존 DB local CREATE 계약은 8개 채널을 지원하지만 TypeScript 수령 허용 목록은 2개만 지원했다. 누락된 6개 CREATE를 맞췄고 나머지 작업 범위는 유지했다. 로컬 실행은 계정·상품·승인된 상세페이지·작업자·IP·배포 버전이 일치하는 기존 경로가 준비됐을 때만 선택된다. Vercel에서 실행 가능한 채널을 모두 Mac으로 강제 이동하지 않는다.

11번가·Lazada처럼 로컬 경로가 필요한 등록은 기존 Mac 작업자를 사용한다. Lazada 정책 테이블의 허용 목록 누락은 migration `20260913122015` 한 개로 수정·운영 적용했다. 기존 승인 경로의 이전 배포/교체 전 credential 참조는 같은 판매자·발급 관리자임을 확인한 뒤 갱신했다. 승인자·소유자·기간·작업 종류·작업자·IP는 보존했다.

이 문서는 전 채널 실작동 완료 선언이 아니다. 최신 배포 버전과 남은 인증 제한은 `현재상태.md`의 최상단 기록을 따른다.

## 배포 인도표

운영 코드 `0b24e61`, Vercel·DB·Mac 버전 일치 확인. 표의 경로는 상품 등록과 CS 수집 기준이다. 수동 답변은 Vercel에서 접수 후 기존 CS 전송 작업자가 처리하며 아래 CREATE 경로 승인을 답변 권한으로 확대하지 않았다.

| 채널 | 상품 등록 구현·배포 | CS 수집 / 답변 구현·배포 | 등록·수집 실행 경로 | 실제 확인 |

| 스마트스토어 | 반영 | 상품·고객 문의 / 지원 답변 반영 | Vercel | 사용자 대기 |
| eBay | 반영 | 지원 메시지 / 지원 문의 답변 반영 | Vercel | 사용자 대기 |

Mac이 꺼지거나 실행 작업자·IP·승인 기간이 달라지면 로컬 경로가 준비 상태를 잃을 수 있다. 이는 판매채널에 전달됐다는 뜻이 아니며 화면의 해당 오류를 확인한다. 자동 검사·배포 인도와 실제 채널 처리 성공은 별도로 판단한다.
