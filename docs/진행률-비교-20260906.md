## 4-1. 게시가 0/8인 진짜 이유 (14:25 확정)

상세 승인이 모자라서가 아니다. **전역 게시 게이트가 요구하는 `reconciliationRequired = 0`이 현재 코드에서 도달 불가능하다.**

- 전역 카운터는 listing.create/update/stop의 `reconciliation_required`를 예외 없이 센다. 현재 정확히3건: qoo10 `089467c1`, shopee `99d3b370`, elevenst `b9faa28e`.
- 그러나 exact 복구 설계는 원본 접수기록을 **영구히 recon으로 보존**하도록 계약돼 있고, 11번가는 불변 트리거로 수정을 막는다.
- 예외 헬퍼는 Qoo10 한정 카운터·개방 SQL에만 적용돼 있고 전역 카운터에는 없다.
- 즉 강제 상태변경·삭제 없이는 전역 게이트가 열리지 않는다. 이건 외부 채널 문제가 아니라 **우리 코드의 설계 공백**이다.
- 올바른 해결은 건수 조작이 아니라, 기존 불변 증거 기반 예외 계약을 전역 카운터에도 같은 기준으로 적용하고 shopee/elevenst용 증거 술어를 새로 정의하는 것이다. 검토 SQL과 사후검증이 필요해 이번 턴에서 적용하지 않았다.

## 5. 지금 이어가는 순서

1. 진행 중인 Lazada exact 세션의 정상 start·공식인가·단회교환·seller readback을 처리한다. 기한·계정·토큰/lease가 안 맞으면 같은코드를 재시도하지 않는다.
2. 가능한 채널의 게시 조건을 각각 해소하고 승인v2를 기존채널별정규화/검증경로로 게시한다. 우회스텁·임의가격·배송값 없음.
3. Shopee 추가인증처럼 사용자 한 단계가 꼭 필요한 항목만 별도 남기고, 나머지 채널/문서작업을 계속한다.
4. 각 실제 결과를 운영진행과 이 비교표에 추가하고 선별검사·커밋한다.
