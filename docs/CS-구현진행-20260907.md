- 접근권한: 인증된 관리자이면서 본인 owner_id인 실제 티켓만 조회한다. 다른 owner·demo·익명 요청은 차단한다. 공유 관리자 열람 정책 확대는 별도 명시적 권한 설계가 필요하다.
- 답변 상태: 기존 succeeded는 채널 접수로 표시한다. 실제 원격 메시지를 수집한 상태와 구분하며 고객 열람으로 표시하지 않는다. 초안을 발송된 답변으로 만들지 않는다.

## 검증

- 채널별 이력 DB 동작 6/6: 스마트스토어 단독, 쿠팡 차단, 쿠팡 단독 25개/두 채널 27개 최초 작업, 입력/권한, 안전한 재시도, 자격 교체·소유자 불일치.

- 기존 CS 조회/답변/상태/내비게이션 회귀 25/25.
- TypeScript 및 변경 모듈 ESLint 통과. 최신 통합 브랜치와 병합 후 운영용 Next 빌드도 통과했다.
- 브라우저 컴포넌트 시험: 합성 데이터만 사용해 최근 대화→이전 대화 추가→시간순 표시, 접수 상태 구분을 확인했다. 실제 판매자센터나 운영 로그인 E2E 시험은 아니다.
- 운영 DB의 이력 생성·집계·enqueue 함수 정의와 ACL을 읽기 전용으로 확인했다. 집계/helper 본문은 감사한 기존 마이그레이션과 일치한다. 시작 wrapper는 이후 스마트스토어 송신 제한 복원 버전이므로 이력 파일의 최신 정의를 함께 대조했다.

## 1차 시점의 잔여 범위 — 현재 상태는 상단 3차 기록 우선

이번 변경은 한국 두 채널의 **7~30일** 이력 요청 분리다. 임의 시작일·모든 채널의 장기 이력 작업, 원격 건수 대조, 채널별 다중 진행 패널, 전체 티켓 검색 API는 계속 남아 있다.

대화 화면은 **이미 원장에 들어온 메시지와 전달 기록**을 표시한다. 채널 API 응답에서 기존 판매자 답변을 추가 수집하는 작업, 첨부·수정 이력, 앱 발송 후 원격 확인의 완성은 아직 남아 있다. 메시지 body가 변경된 과거 revision을 이 API가 새로 복구하지 않는다.

쿠팡 송신 경로, Lazada 판매자 신원/권한·비텍스트 메시지, Shopee·11번가·Temu 앱/CS 계약, 채널별 실제 수신/답변 검증과 48시간 운영 관측은 미완료다. Chrome 탭 목록은 확인했으며 일부 탭은 로그인 URL을 표시하지만 현재 세션 만료 여부를 실제 페이지에서 확정하지 않았다. 이번 구현에는 판매자 Chrome 페이지 조작을 사용하지 않았다.

## 운영 적용 순서

1. DB 실제 정의와 대상 프로젝트를 다시 대조하고 `20260907100000_scope_cs_history_by_channel.sql`, `20260907101000_read_cs_conversation_timeline.sql`을 순서대로 적용한다.
2. 같은 변경의 API·웹 배포 후 함수 노출/권한, 관리자별 대화 조회, 채널 단독 이력 요청을 확인한다.
3. 원격 실제 문의 ID와 DB/UI를 대조한다. 실제 답변은 허용된 문의·수신자·문구를 정한 뒤 수행한다.

이 기록 시점에는 운영 DB 적용, Production 승격, 실제 이력 수집 요청, 고객 답변 전송을 수행하지 않았다. 미적용 API가 있는 웹만 먼저 Production에 배포하면 대화 조회가 실패하므로 DB 선행 적용을 지킨다.
