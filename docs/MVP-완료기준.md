# SellerPilot MVP 완료 기준 — 2026-09-13 사용자 범위 수정

목표는 각 판매채널의 공식 API 요구 사항에 맞는 기본 업무다. 아래 기준은 과거 복구 보고서의 확장 작업 목록·시간 예측보다 우선한다. 기존 구현을 재사용하며, 과거 작업을 처음부터 다시 개발하지 않는다. 이 문서는 완료 선언이 아니라 앞으로의 구현·검증 기준이다.

| 업무 | MVP에서 필요한 동작 |
| --- | --- |
| 계정 연결 | 현재 승인된 계정·권한으로 공식 API 호출. 필요한 인증 문제만 최소 수정 |
| 상품 등록·조회 | 기존 이미지·상세페이지를 사용해 등록하고 채널 상품 ID·결과를 저장. 해당 상품을 조회해 상태 확인 |
| CS | API가 지원하는 실제 문의를 가져오고 사용자가 작성한 답변을 전송·결과 저장 |
| 주문·배송 | 주문 조회, 운송사·송장번호 입력, 공식 발송 API 요청과 결과 저장 |
| 실행 위치 | 웹·일반 API·DB는 Vercel/Supabase. 실제 IP 제한이 있는 호출은 기존 Mac 작업자 사용 |

쿠팡·스마트스토어·11번가·Shopee·Lazada·eBay·Qoo10·Temu를 대상에서 임의로 빼지 않는다. 각 채널의 기본 연결부터 순서대로 검증하되, API 미지원·권한 제한 기능은 구체적으로 표시하고 다른 기능의 완료를 막지 않는다. 모든 국가·계정의 동시 자동화는 첫 MVP의 전제 조건이 아니다.

수동 실행으로 기본 흐름을 끝낼 수 있으면 MVP 방식으로 인정한다. 전체 과거 이력 복원, 실패 작업 일괄 복구, 범용 인증 복구 엔진, 무인 24시간 자동화, 고급 재시도·모든 국가 일괄 연결을 먼저 완성할 필요는 없다. 이미 구현한 기능은 삭제하지 않고 추가 확장을 후순위로 둔다.

기존 DB 함수·인증·저장 문제가 해당 기본 동작을 실제로 막을 때만 그 경로를 수정한다. 과거 누락 함수 숫자나 오래된 보고서를 그대로 재작업 목록으로 삼지 않는다. 기능 하나의 구체적인 실패와 최소 수정 범위를 먼저 연결한다.

계정 소유·권한 확인, 비밀 보호, 정확한 성공/실패 저장, 불확실한 등록·답변의 중복 전송 방지는 유지한다. 상품 등록·고객 답변·송장 전송은 실제 업무 대상과 내용이 정해진 경우에만 실행한다. 검증용 가짜 상품·답변·송장을 만들지 않는다. 로컬 검사 통과, 큐 접수, 배포만으로 채널에서 실제 작동했다고 보고하지 않는다.

현재 준비된 Aside 세션을 우선 사용한다. 사용자가 금지한 새 Shopee 로그인 시도를 반복하지 않는다. 로그인 화면과 API 토큰 상태는 구분하되, 기본 연결에 필요하지 않은 과거 토큰 복구 작업을 확대하지 않는다.

완료 보고는 채널별로 등록·조회·CS·배송의 작동 여부, 실제 확인 근거, 남은 구체적 제한을 짧게 표시한다. 이전 8–13시간 등의 복구 작업 추정치는 이 MVP의 예상 완료 시간이 아니다. 새 일정은 이 기준에서 남은 구체적 기능만 확인한 뒤 산정한다.
