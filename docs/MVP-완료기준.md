## 1. 포함 범위와 업무 흐름

| 영역 | 이번 MVP 흐름 | 개발 인도 기준 |
| --- | --- | --- |
| 상품 준비 | 기존 이미지·상세페이지 제작 결과 선택 → 상품명·가격·재고·카테고리·필수 속성 입력 | 기존 자산을 연결하고 채널 필수 입력 오류를 표시 |
| 상품 등록 | 채널·계정 선택 → 등록 요청 → 채널 상품 ID와 처리 결과 저장 → 등록 상태 조회 | 공식 API 요청 형식과 응답 처리를 구현하고 접수·성공·실패·미확정을 구분 |
| CS | 채널별 문의 가져오기 → 문의 목록·내용 확인 → 사용자가 답변 작성 → 전송 결과 저장·표시 | 문의 신원/대화/답변 연결과 지원되는 API 계약 구현. 시스템 알림을 고객 문의로 세지 않음 |
| 계정 연결 | 위 두 흐름에 필요한 공식 인증·권한·계정 선택 | 실제 차단 조건만 최소 수정. 권한 미확인·미지원 기능은 구체적으로 표시 |

대상은 쿠팡·스마트스토어·11번가·Shopee·Lazada·eBay·Qoo10·Temu다. 임의로 대상 채널을 삭제하지 않는다. 개별 기능의 권한 제한이 다른 사용 가능한 기능의 인도를 막지 않게 한다. 수동 버튼 실행을 허용하며 모든 국가·계정 동시 자동화는 전제 조건이 아니다.

상품 등록 API가 필수로 요구하는 배송비, 출고지·반품지, 배송 템플릿은 **상품 등록 필드**로 포함한다. 주문 수집·발주·송장 전송·배송 추적 구현으로 범위를 확대하지 않는다. CS가 주문 식별자를 제공하면 해당 문의에 보존할 수 있으나 이를 이유로 새 주문 동기화 기능을 개발하지 않는다.

## 2. 실행 구조

- Vercel: 상품 등록/CS 화면, 인증된 요청 접수, 일반 채널 API 호출, 결과 표시.
- Supabase: 상품·문의·답변·처리 결과와 기존 인증 정보 저장. 해당 흐름에 필요한 DB 변경만 적용.
- 기존 Mac 작업자: 실제 IP 제한이 있는 채널 호출과 기존 로컬 이미지 제작 실행. 새 범용 실행 체계를 만들지 않는다.
- 채널별 기존 실행 경로를 유지한다. 기능 실패 증거 없이 전체 채널을 로컬로 옮기거나 연결을 다시 승인하지 않는다.

## 3. 작업 순서

1. 이미 구현된 상품 등록/CS와 Lazada 최신 변경을 대상으로 배포 인도 범위를 고정한다. 이미지 압축·상세페이지·기존 DB 함수 전체 감사를 반복하지 않는다.
2. 상품 등록의 필수 입력 → 기존 채널 어댑터 → 결과 저장/화면 표시에서 확인된 누락만 수정한다. 새로운 일반 상품 관리 기능은 추가하지 않는다.
3. CS의 수집 → 문의 표시 → 수동 답변 → 결과 저장에서 확인된 누락만 수정한다. Lazada는 작성한 국가별 처리 코드를 재사용한다.
4. Shopee는 상품 등록/CS를 막는 최소 인증 문제만 처리한다. 준비된 Aside 탭을 사용하며 새 로그인 시도를 반복하지 않는다. Temu 일반 상담은 공식 계약·권한 확인 후 지원 범위를 구현한다. API 명세를 추측해 넣지 않는다.
5. 관련 자동 검사와 필요한 빌드 후 Vercel·해당 Mac 실행본을 반영하고 사용자에게 확인 순서를 전달한다. 사용자는 실제 채널에서 등록/문의/답변을 검증한다.

독립된 상품/CS 파일 작업은 기존 소유 범위에서 병렬로 처리할 수 있다. 공통 DB·Git·배포는 한 통합 담당자가 순서대로 처리한다. 작업끼리 메시지 교환이나 신규 작업방 생성은 이 설계의 요구 사항이 아니다.

## 4. 이번 범위에서 제외

주문 관리·주문 동기화, 11번가 발주/발송, 운송사·송장 전송, 배송 추적, 물류 자동화는 모두 후순위다. 기존 코드·데이터·실행 중 설정을 임의로 삭제하거나 중지하지 않는다. 이 기능들의 미완성을 상품 등록/CS 인도 차단 조건으로 삼지 않는다.

과거 실패 작업 일괄 복구, 전체 이력 수집, 범용 토큰 복구 엔진, 무인 24시간 자동화도 인도 전제 조건이 아니다. 계정 권한·비밀 보호·정확한 결과 저장·불확실한 요청의 중복 전송 방지는 유지한다.

## 5. 역할과 인도물

개발 담당은 구현·필요 DB 반영·영향 범위 검사·빌드·배포와 짧은 사용자 확인표를 제공한다. 실제 상품 등록이나 고객 답변을 대신 실행하며 검증 완료를 기다리지 않는다. 사용자가 발견한 오류는 해당 기능 범위로 수정한다.

인도 확인표는 각 채널별로 `상품 등록 개발/배포 상태`, `CS 수집 개발/배포 상태`, `CS 답변 개발/배포 상태`, `Vercel 또는 Mac 경로`, `권한/명세 제한`, `사용자 실검증 대기/결과`를 표시한다. 로컬 검사 통과·큐 접수·배포를 원격 작동 완료로 표시하지 않는다.

이번 변경은 설계/작업 범위 수정이며 기능 구현 또는 새 배포 완료 선언이 아니다. 앞서 배송을 포함해 제시한 총 5–8시간은 폐기한다. 이미 구현된 기능의 1차 배포 인도는 기존 잠정 예산 1–2시간을 유지하되, Shopee 인증과 Temu 일반 CS의 미확인 범위를 포함한 전체 완료 시간은 확정하지 않는다. 향후 예상에는 상품 등록/CS에 필요한 작업만 포함한다.
