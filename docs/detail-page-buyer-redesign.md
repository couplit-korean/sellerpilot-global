# 구매자 중심 상세페이지 출력

2026-09-07: 최신 main의 서버 생성 경로에 적용. 기본 프롬프트는 `contentDensity=concise`, 본문 8~12개(기본 8개), 20~120자 중심(최대 240자), 포인트 0~3개를 요청한다. spec과 caution은 필수다. 8개 이미지 역할을 현지화 전체와 동일하게 유지한다. 기존 long/deep-dive 문서 및 장애 시 검수 입력으로 만드는 16개 섹션의 안전한 fallback은 계속 지원한다.

## 생성과 출력

- `lib/server-product-studio.ts`: 운영 서버 생성 지침과 정규화. 간결형 문서를 과거 12개 이미지/9개 정보유형으로 강제로 확장하지 않는다.
- `scripts/ai-cli-worker.mjs`, `scripts/ai-studio-output.schema.json`: CLI 경로도 동일한 기본 지침을 사용한다.
- `lib/ai-cli-contract.ts`, `lib/studio-segment-generation.ts`: 간결형 길이, 중복 이미지, 현지화와의 역할 일치 검증. 기존 일반식품 효능·섭취량·분류·언어 검증은 유지한다.
- `app/product-detail-buyer.tsx`, CSS: 실제 미리보기에서 큰 제품 이미지, 여백, 제목 중심 구성. 검수용 buyerQuestion/evidence는 문서에 보존하고 화면에서는 숨긴다. 주의사항은 표시한다. 이미지 로딩 성공/실패 보고와 GIF 대체 표시는 유지한다.
- `app/_publishing/product-detail-html.ts`: 저장 문서의 채널용 HTML에도 검수 문구와 가짜 CTA 버튼을 제거한다. 이미지 역할 토큰 8개를 보존한다. 채널 HTML은 호환성을 위해 세로 배치와 인라인 스타일을 사용한다. 해외 현지화 설명의 별도 템플릿과 각 마켓의 렌더링은 별개다.

## 등록과의 관계

상품 등록 API, 가격·재고·물류 입력, 승인 manifest/원본 digest 계약은 변경하지 않는다. 등록은 기존의 정확히 8장 상세 이미지 검증을 통과해야 한다. 생성 자산 전체는 기존 16종 계약을 유지하며 그중 선택한 8개를 상세에 배치한다. 실제 상품의 라벨·구성·브랜드를 새로 그려 사실처럼 사용하는 방식은 허용하지 않는다.

## 확인 범위

첨부 상품으로 만든 이전 예시는 수동 아트디렉션 시안이다. 이 변경은 같은 디자인 방향을 자동 생성의 기본값과 실제 출력에 연결한다. 모델의 문구/이미지, 입력 사진, 기존 승인 자산, fallback, 채널 HTML 제약에 따라 결과는 달라질 수 있으며 예시와 픽셀 단위 일치를 보장하지 않는다. 기존 저장 상품의 이미지는 자동으로 교체되지 않는다. 실제 생성 완료와 판매채널 게시 완료는 각각 별도로 확인해야 한다.
