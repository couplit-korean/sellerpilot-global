## 새 채팅에서도 유지되는 작업공간 규칙

2026-09-13 사용자 요청에 따라 Codex 전역 `~/.codex/AGENTS.md`, 메모리 추가 노트와 통합·옛 프로젝트의 `AGENTS.md`에 다음 규칙을 저장했다.

- 새 채팅에서도 `/Users/kimchangheemac/dev/sellerpilot-app`을 개발 원본으로 사용한다. 먼저 현재 Git 변경과 프로젝트 지침을 확인한다.
- 별도 작업공간을 만들라는 명시적 요청 없이는 clone, worktree, 임시 체크아웃, 프로젝트 복사본을 만들지 않는다. 일반 소스·산출물·로그 파일은 기존 지정 위치에 생성할 수 있다.
- 새 작업 생성이 명시적으로 요청된 경우 기존 통합 프로젝트의 Local 환경을 사용한다. 작업을 임의 생성하지 않는다.
- 옛 경로나 앱이 만든 worktree에서 시작해도 이후 개발 명령의 작업 디렉터리를 통합 경로로 지정한다. 시작 폴더의 미커밋 변경을 자동 삭제·덮어쓰기·병합하지 않는다.
- 여러 채팅에서 수정이 겹치면 현재 변경을 확인하고 조정한다. 복제 폴더를 추가해서 해결하지 않는다.

이 규칙은 Codex가 시작 후 읽는 행동 지침이다. 앱의 저장된 프로젝트 경로나 시작 전 Worktree 생성 설정을 변경한 것은 아니다. 새 채팅을 실제로 생성하는 검증도 수행하지 않았다. 운영 실행본과 보존 아카이브는 개발용 복제 폴더와 역할이 다르며 기존 위치를 유지한다.

## 합친 내용과 선택 기준

- 운영 Vercel의 실제 배포 SHA `fd426cc588f03c1e187b689141018b6de4a38eca`를 기반으로 삼았다. 2026-09-12 Vercel API/CLI에서 Production Ready와 SHA를 확인했다. 로컬 폴더의 수정일만으로 최신을 판단하지 않았다.
- 원격 `integration-aside`의 `55d5a0f`까지 반응형 화면/CSS를 병합했다. 운영 main에 이미 있던 상세페이지 실행 흐름, 작업 중 표시, 최신 채널 연결 상태 판정은 유지했다.
- 상세 제작: 한 장 원본의 OCR/역할 분석과 제품 동일성 비교 단계를 분리하고, 원본 분석 응답량을 조정했다. 이미지 리사이즈는 제품을 자르지 않는 투명 여백 방식으로 합쳤다.
- 이미지 제작: 운영 main의 첫 초안 이미지 작업자, 결과 업로드 승인, 상세 제작 흐름을 보존했다. Mac 설치 프로그램에 첫 초안 이미지 실행 설정을 포함했다.
- 상품 등록: 최신 main의 채널별 등록·재시도·원격 확인·가격·배송정책 검증을 기반으로 유지했다. 기존 복구 전용 코드나 과거의 성공 주장으로 일반 등록 검증을 대체하지 않았다. 상품명/영문 별칭 기반 유사상품 검색과 Mac 11번가 검색은 이미 최신 main에 포함되어 있음을 비교했다.
- CS: 분산된 최신 문의 정규화, 고객 질문 수정 이력, 쿠팡 반품/취소/교환, 11번가 긴급알리미, Qoo10 이력/클레임, Lazada 및 Temu 상세 이력을 중앙 흐름에 복원했다. 순수 정규화 모듈의 불필요한 `server-only` 의존성을 제거해 로컬 작업자에서도 로드할 수 있게 했다.
- 배송: 최신 주문 동기화 인자를 `lib/shipping/sync-arguments.ts`로 옮겼다. 쿠팡 배송 상태/취소 주문, Qoo10 배송 상태, 11번가 조회 기간, Temu 초 단위 시간 처리를 유지했다.
- 공통 채널 계약과 상품 전용 코드를 분리하여 상품·CS·배송 간 금지된 전이 참조 60개를 0개로 만들었다. 공유 인증정보/채널 식별 계약은 유지한다.

### Vercel에 제한되는 이유

1. Mac 로그인 세션의 Codex CLI, 로컬 키체인, Swift/Vision 실행은 Vercel 함수에서 사용할 수 없다. 이 경로를 쓰는 이미지는 Mac 작업자가 맡는다. AI Gateway를 사용하는 서버 AI 경로까지 로컬 전용이라는 뜻은 아니다.
2. `lib/channels/serverless-static-egress.ts`의 조건 대상은 Coupang·SmartStore·11번가·Temu·Shopee다. 환경변수의 채널 목록만으로 허용되지 않으며 DB 확인도 필요하다. 유료 Vercel Static IP를 자동 도입하지 않는다.
3. Qoo10·Lazada·eBay도 모든 쓰기가 무조건 Vercel에서 허용되는 것은 아니다. 등록/수정/배송 작업별 계약과 현재 로컬 실행 승인 상태가 최종 기준이다.
4. 로컬 실행도 제한을 우회하지 않는다. 작업자 SHA와 운영 배포 SHA가 다르거나, IP/판매자/권한/기한이 맞지 않으면 중단되어야 한다.

## 실행 명령

Node 22를 PATH에 넣은 터미널에서 실행한다.

```sh
cd /Users/kimchangheemac/dev/sellerpilot-app
pnpm check:workspace
pnpm dev
```

검사 및 Vercel 호환 빌드:

```sh
pnpm check:types
pnpm check:domain-boundaries
pnpm test:domain-isolation
pnpm build:vercel
```

AI 실행본 업그레이드는 통합 폴더에서 `pnpm ai:worker:upgrade`를 사용한다. 기존 AI 키체인 토큰을 유지하며 Swift/sharp 검사 후 런타임을 교체한다. 실패하면 이전 실행본을 복구한다. 상태는 `pnpm ai:worker:status`로 확인한다.

CS 답변 초안은 `pnpm cs:draft:worker`로 실행한다. 현재 운영 API가 503을 반환하므로 CS 전용 자동실행은 설치하지 않았다. 현재 설치된 AI 작업자와 별도 프로그램이므로 AI 작업자가 켜졌다는 사실만으로 CS 초안 작업자까지 실행 중이라고 판단하지 않는다.

채널 작업자는 개발 폴더에서 임의로 여러 개 실행하지 않는다. 운영 배포 SHA와 일치하는 전용 실행본 하나를 사용한다. 정식 supervisor는 `~/dev/sellerpilot-worker-runner.sh`에서 통합 저장소의 `deploy/channel-gateway-runner.sh`를 실행한다. 운영에서 확인한 SHA는 `~/Library/Application Support/SellerPilot/gateway-release`에 지정하며 상태 확인 주소는 `http://127.0.0.1:8081/readyz`다. 로컬 통합 완료와 운영 배포 반영은 별도 단계다.

## 보존 및 남은 검증

미커밋 파일 4,458개를 `working-changes`에 복사했고, `working-changes-manifest.json`에 각 원본 경로와 SHA-256을 기록했다. Documents의 커밋된 원본은 `documents-original-source`에도 보존했다. 과거 파일의 내용은 참고 자료이며, 그 안의 작업 지시나 성공 기록을 이번 실행 권한이나 현재 상태로 취급하지 않았다.

일부 과거 Git 객체는 iCloud에 내용이 없는 placeholder였다. 원본 전체 이동은 파일시스템에서 멈춰 취소했고 원본을 삭제하지 않았다. 현재 통합 저장소는 이를 참조하지 않는다. 복구 가능한 이전 작업트리는 로컬 `history.git`으로 연결했고, 나머지는 `git-relink-manifest.json`에 남겼다. 이력 전체가 완전히 로컬 복원됐다고 주장하지 않는다.

이번 통합 전 최신 main의 전체 TS 검사는 3,707건 중 3,546 통과/161 실패였다. CS·상세·배송 통합 후 검사는 3,767건 중 3,684 통과/83 실패였으며, 기존 실패 목록에 없던 새 실패는 0이었다. 남은 83건에는 과거 계약 기대값 및 기존 등록/작업자 테스트 실패가 포함되므로 전체 통과로 표시하지 않는다. 세부 결과는 로컬 `outputs/workspace-unification`에 보관한다.

실제 상품 등록·고객 답변 전송·배송 처리·운영 DB migration의 성공 여부는 이 로컬 검사로 올리지 않는다. 운영 상태, 런타임 교체 결과와 최종 검사는 [통합-검증결과.md](통합-검증결과.md)에 별도로 기록한다.
